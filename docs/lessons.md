# Lessons

Failure modes that have actually happened, and the guard that now catches each
one. This is not a style guide and not a wish list.

The point is the shape, not the incident. A bug that can only happen once
is not a lesson. A bug whose shape recurs is. Read this before adding a guard,
because the shape is usually already here.

Keel's catalogue is the **central** one. Each row says where it was paid for,
e.g. *(ledger 6)*, *(isocan)*, *(duo 4)*. A guard marked *planned* names the
phase that builds it; nothing is claimed as guarded until it is. Projects
send new rows home with `keel lessons` (phase 7), and `keel learn` decides
them here (phase 8).

| # | The shape of it | What it cost | Guard |
| --- | --- | --- | --- |
| 1 | **A copied practice ages, and can't hear that the original changed.** Every hand-port of a skill or an AGENTS.md section is a fork with no upstream. *(keel, observed 2026-10-02)* | isocan kept an untracked second copy of its conduct skill under `.agents/skills/`, dated 20 Sep. By 2 Oct it was missing a week of changes to the real one in `.claude/skills/`, including `7227f325`. A reader of the wrong copy would have run the expensive version. Across the fleet, duo, cajones and ledger each carry a different hand-port of the same phase practice. | One file, many doorways: a skill lives once, under `.agents/skills/`, and `.claude/skills/` is a symlink. Adapted files pin their `source` commit. *Planned:* `keel doctor` reports second copies and drift (phase 5), and `keel learn` polls sources (phase 8). |
| 2 | **Status written in more than one place drifts, and both copies look authoritative.** *(ledger 6, duo 1, cajones)* | In ledger, the README said phase 2 was complete while SPEC.md said phase 4 was built. Both had been hand-edited the same day. | Status lives in each phase's front matter. `docs/ROADMAP.md` is derived from it, and `npm run roadmap:check` fails CI when the roadmap is stale, a claim lacks evidence, or a dependency loops. *Implemented on keel* (phase 0). |
| 3 | **A guard that fires into a room nobody is in.** *(ledger 8, duo 2)* | CI was red on three consecutive commits and production served an eight-hour-old build. Both were found by accident. | Every nightly and deploy check fails as a *workflow*, which GitHub emails about. It is never only a page. *Planned:* phase 10 asserts it. |
| 4 | **A green subset hides a red suite.** `npm test \| tail` reports tail's exit code, and a fast lane leaves out the files a change broke. *(isocan house rules, conduct)* | In isocan, a green subset hid a real failure three times in one week. Each time the failure was in a file the change didn't name. A subagent reported "suite passed" while six tests failed. | The conductor reads exit codes, not tails, and runs the whole check once on the integrated tree before landing. *Implemented* in the conduct skill. |
| 5 | **Verification repeated at every level costs more than it catches.** *(isocan `7227f325`)* | In one conducted session, builders ran the whole suite 53 times (2.8 hours, a quarter of all subagent time) and typecheck 56 times. The conductor's own deep run then repeated all of it. | Builders test the files they touched. The conductor runs the full check once, detached. Briefs point to docs rather than paste them, and stay under 600 words. *Implemented* in the conduct skill. *Planned:* the cost is measured by `keel improve` (phase 11). |
| 6 | **A grader that reports zeros when it breaks is believed.** *(isocan evals, lesson 8 there)* | isocan's first grader scored a stretched image 8/8, because its probe threw and every reading fell to empty. | A self-test on a fixture built to fail must fail every check before a run counts. An instrument that can't run exits non-zero. *Planned:* phase 11. |
| 7 | **A guard that stores a copy of a fact instead of deriving it.** *(ledger 12)* | ledger's CI hard-coded "install web/ only". When the fact changed, the copy became wrong in both directions and the comment defended it. | Read the single statement of the fact (the deploy config, the practice manifest) in the test, never restate it. Keel's version of this is `practice.json` (phase 1). |
| 8 | **A fake that mirrors the implementation can only confirm it.** *(ledger 11)* | ledger's fake Gmail matched labels by id, exactly as the buggy code did. The tidy-up found nothing for weeks and reported success. | Fakes model the third party's real behaviour. Keel stubs `gh` at the boundary, with recorded real responses. |
| 9 | **Machine pull requests pile up without a drain.** *(isocan night shift)* | Five open machine PRs at once in isocan on 9 Sep 2026. Each was waiting on a person to remember it. | A workflow's queue holds at most one open PR, the newest, and the run drains its predecessors itself. *Planned:* phase 10. |
| 10 | **A commit step that can't see a first-time file.** `git diff --quiet` compares against the index, so a newly created file reads as no change. *(ledger audit workflow)* | ledger's audit agent lost every report it had ever written. An empty report is what a healthy audit looks like, so nothing seemed wrong. | Workflows test `git status --porcelain`, and push with a rebase-and-retry loop. In local gates, the conductor runs `git add -N` on new files before checks that use `git ls-files` (isocan lesson 70). *Planned:* phase 10's workflow test. |
| 11 | **A check that dispatches events proves the handler, not that a person can reach it.** *(duo 4)* | 25 duo examples shipped "verified" in poses where no real tap could reach them. | Where a person's input matters, drive real input (CDP `Input.dispatchMouseEvent`) and say so in the evidence. Per kind, not fleet-wide. |
| 12 | **A tool built for one version of a service, silently incompatible with the next.** *(duo 3)* | duo's `isocan` CLI couldn't create a canvas on the hosted home, and `upgrade` refused to help. | When a CLI talks to something versioned, check the other side's version first. For keel this means `keel update` updates the CLI before it runs any migration (phase 6). |
| 13 | **A tool that restores its own copy erases the edit it should have reported.** A renderer that makes the tree match its template is "correct" every time it runs, and each run deletes the one piece of evidence that someone needed it to be different. *(keel, phase 5)* | `keel render` silently overwrote a project's edit to a managed file. Phase 1's own tests asserted this as the right behaviour ("a second render restores managed files"). It was found only when phase 5's builder asked what render does to a file that doctor calls `edited`. | `render` refuses to write over an `edited` or `both` target (exit 1, nothing written) and points at `keel doctor --fix restore\|eject`. `tests/doctor.test.mjs` asserts the refusal for a file and for a block. |
| 14 | **A check spawned from inside a test runner inherits the runner's context and passes while running nothing.** Node's `node --test` sets `NODE_TEST_CONTEXT` for its children, and a child `node --test` that sees it runs no files and exits 0. *(keel, phase 6)* | Every keel test that spawned a project's own `npm run check` (init, adopt, practices) had been green while measuring nothing since phase 1. A test file that only throws exited 0. Found by phase 6's builder, when its gate assertion passed although the project's tests had been deleted. | All spawns go through `tests/helpers/run.mjs`, which strips `NODE_TEST_*`. Every spawned gate also asserts that tests ran and names one. `tests/helpers.test.mjs` fails on a failing child that exits 0, and on any raw spawn in a test file. `keel update` strips the same variables before it runs a project's check. |
| 15 | **A version gate decides who gets a fix, and anyone who arrives after the version never gets it.** "Apply what's newer than you" assumes every project started at the beginning. *(keel, phase 6)* | Migration 0001 (`to: 0.1.0`) could never run on ritmo: adopt stamps the current practice, so a project adopted at 0.1.0 is "already on 0.1.0". Every test passed, because the fixtures started at 0.0.0. Found on a walk against a fresh clone of the real project. | Migrations run when `applies()` is true and aren't yet recorded in the project's `migrations` list. Version comparison stays only for "update keel first". A test adopts at the current version and asserts 0001 runs. |
| 16 | **A doc that restates what the code knows goes stale silently.** A README verb table, a feature list or a "planned" label is a hand-kept copy of a fact the code owns. Nothing fails when the two part ways, so the doc keeps saying the old thing in a confident voice. *(keel, observed 2026-10-03; ledger 6 and 12 are the same shape)* | keel's README called every verb "planned" through eight phases that built them, and was missing `drain`, `phase`, `render` and `fleet update`. The agent guide stayed current over the same eight phases, because a test reads the verb registry against it. The README had no such test. The owner found it by asking whether a README explained keel. | `tests/docs.test.mjs` (phase 18) reads the live verb registry and the `practices/` directory and fails when the README's verb and practice tables miss one, list one that doesn't exist, or call a built verb "planned". Conduct's Record step asks "does this change what a person or an agent is told?" and updates README and the agent guide in the same commit. "Remember to update the docs" is not a guard. On its first run the test found `base` missing from the practices table, in the README rewritten by hand that morning. |
| 17 | **A test whose injected value doesn't reach every path is green only while the real value happens to match.** The test set the CLI version in-process, but a spawned CLI at its end read the live `package.json`. Nobody noticed, because live and injected were the same number. *(keel, v0.3.1)* | Cutting v0.3.1 turned CI red on the release commit itself: one fixture project became "behind". The release step hadn't run the gate, and the conductor ran the check *before* releasing, not after. CI was the first reader. | Fleet verbs take the version through `KEEL_FLEET_PRACTICE` in tests, so the spawned CLI gets it too. A regression test injects versions far above and far below the live one. `keel release` now runs the project's gate after the bump and before committing; on red it restores every file and makes no commit and no tag. |
