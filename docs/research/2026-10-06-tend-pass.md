# The tend pass: keeping the records true

Design, 6 October 2026. Phase 38 builds it; phase 32 adds the measure it
reads first.

## Why a third pass

The measuring night (phase 10) finds record problems every night: a stale
roadmap, stuck phases, drift from keel's files, practice lints, placeholder
evidence, and, with reconciliation on (phase 26), records that contradict
what was delivered. It reports them; nobody fixes them until a person
notices. On 6 October the conductor fixed several by hand in one day: a next
action asking for a red night already proven, a lessons header behind its
practice, docs behind the code.

Climb nights (phases 35–37) improve a number. This is different work: the
records should say what is true, and the measure of success is that the
night's record findings reach zero, either fixed or decided. So it is its own
pass, sharing the climb workflow's machinery but not its protocol.

| Pass | Does | Success | Cost |
| --- | --- | --- | --- |
| Measure | reads the project, writes the health page | — | free, nightly |
| Climb | makes one number better | the number moved past noise | opt-in, model budget |
| **Tend** | keeps roadmap, phases, docs and keel's files true | record findings reach zero | opt-in, model budget, weekly by default |

## What tend reads

All from the measuring night, deterministic:

- **`proofs_hold`** (new, phase 32): every built phase's cited tests still
  exist and passed in the last recorded run (phase 33's ledger), and every
  path its evidence names still exists. A built phase that fails is flagged
  *proof lost*, never stepped back to partial by the night.
- Reconciliation's proposals (phase 26), when the practice is on.
- `roadmap_stale`, `phases_stuck`, `evidence_placeholders`, `drift`,
  `lint` (including `acceptance-unchecked` and `readme-behind`).
- `keel loose-ends`' items for the project.

## What tend may do, and what it may not

In one PR on `keel-tend/<date>`, which a person reads and merges:

- **Apply** reconciliation's proposed corrections, and refresh a next action
  whose step is already done.
- **For a lost proof**: repair the reference if the test was renamed (the
  ledger shows the new name ran), or propose stepping the phase back to
  partial with the reason. **Never write evidence**; never mark built,
  lived-in or accepted.
- **Docs**: bring README and agent-facing text back in line with the code,
  citing the code it read.
- **Drift**: say, per drifted file, keep (eject), restore, or send home, with
  its reason; the PR describes, the owner chooses (`keel doctor --fix`).
- **Loose ends**: list what looks finished (a merged branch, an abandoned
  PR) with the command to close it; never delete a branch, a PR or data
  itself.

A finding it cannot resolve within budget stays on the health page, named,
with what tend tried. Record edits are never merged by machinery: phase 26's
rule.

## Judged by

The count of record findings on the health page, week over week, and whether
the owner merges what tend proposes. A pass whose PRs are closed unmerged
three times in a row proposes its own retirement, as climb jobs do.
