# Evidence: phase 81 — production is checked by the commit it serves

- Date: 2026-10-17
- Phase: [81](../phases/81-production-is-checked-by-the-commit-it-serves.md)
- Revision: base `b8b86c6` (main, phase 80 merged), then `9208f3c` (#179's
  fix) and the working tree on `claude/phase-81`.
- Claim being checked: the delivery practice's `scripts/keel/verify.mjs <sha>`
  passes only when production's version path reports that commit or a
  descendant (ancestry in the checkout) and every smoke check matches, retries
  within a bound, and fails naming each check otherwise; `verify.mjs live
  <sha>` says yes for the commit or a descendant and no otherwise; `--record`
  puts the result on the branch `keel-verify`, where a failed latest verify is
  the owner's item on `keel board` and each failure of the day before a night
  is a line in that night's morning brief; `delivery.site`, `version` and
  `smoke` are validated with errors naming the key, in the verifier and in
  `keel doctor`.

No real project and no external network: production is a stub HTTP server on
127.0.0.1 in the test process; every repository is a synthetic Acme bare
origin and a clone in a temp directory, so ancestry is real git.
