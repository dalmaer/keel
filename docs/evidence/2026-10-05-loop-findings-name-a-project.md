## By hand

The copy comparison, from a scratch directory `C` (isocan at `ea9983851`,
read-only; nothing written to it):

```bash
mkdir -p C/docs C/scripts C/.keel
cp -R isocan/docs/loop isocan/docs/LOOP.md isocan/docs/projects C/docs/
cp isocan/.keel/keel.json C/.keel/ && cp isocan/.stitch.json C/
cp keel/practices/loop/files/scripts/loop.mjs C/scripts/
# set C/.keel/keel.json "loop": {"intro": [the eight lines of isocan's intro paragraph]}
cd C && node scripts/loop.mjs render --check   # against isocan's own page
cp docs/LOOP.md ../LOOP.isocan.md && node scripts/loop.mjs render && diff ../LOOP.isocan.md docs/LOOP.md
```

## Gaps and decision

- isocan's hedge rule and model proving are ported, both opt-in
  (`loop.hedge`, `loop.prove` + `ANTHROPIC_API_KEY`), so ledger's findings
  stay valid and nobody spends on a model by default. Proving was never run
  against a real model here, only the stub. keel's `keel-loop.yml` does not
  pass the key: that is the owner's ⚑ step.
- keel writes front matter as ledger's YAML does (`loop` as a list); the first
  `propose`/`decide` reformats an isocan finding it touches. The page is
  unaffected; parsing isocan's flat form is covered by the comparison above.
- Not walked: `push` against a real Loop workspace from a projects-shaped repo
  (the context's `project` field is tested only against the stub).
- Supports **built**: both acceptance lines are observed. Lived-in waits on
  isocan retiring its own script.
